## Notes for the record (from validation, all resolved)

- The firmware **re-centers the joystick on every boot**
  (`initJoystick` → `setJoystickInitialization`), which explains the
  long-observed boot-to-boot neutral "drift" — it is by design, not drift.
  The completion used to print `SUCCESS,0:IN,1:<point>` with hardcoded
  flags, producing an unsolicited SUCCESS when a serial session was open
  ~2 s after boot (one stray line observed mid-load during validation).
  **Fixed in firmware 4.5.2:** the ack type now follows the initiator —
  `SUCCESS` only for a host-requested `IN,1:1`, `MANUAL,0:IN,1` for every
  device-initiated center (boot auto-center, Hub-menu Center Reset, the
  calibration's internal step 5). Same data, matches no command waiter, so
  a boot straggler can never falsely resolve a pending center request. The
  app gates its "Neutral position updated" status on SUCCESS and treats
  MANUAL pushes as readouts (`tests/flows.test.mjs` pins both wire
  generations plus the straggler case).
- The battery trade from the XENSIV migration ("the sensor now measures
  continuously") **is closed as MOOT, with hardware evidence:** the
  LipSync has no internal battery — the BOM is a Xiao nRF52840 powered via
  the hub USB cable, with no cell or charger in the parts list. Every
  powered state is externally fed (host USB, or the phone over USB-OTG for
  mobile use — the case the User Guide already steers to an external power
  source). There is no device-battery-life metric for the continuous
  current to affect; the powerdown-mode follow-up documented in the vendored
  copy's `LIPSYNC.md` stays documented but unneeded. The upstream #37 draft
  now carries the finding for other migrators.
- A degraded boot's auto-center can store a garbage-neutral (observed
  `0.00|0.00` during the unseated boot); the corners survive and a clean
  `IN,1:1` restores it — exactly what the bench did. (Inherent to
  re-centering at boot on a garbage-ACKing bus; the read path is bounded
  either way.)
- `Firmware update check failed: Failed to fetch` lines during validation
  were the app's remote update-check with no server reachable — unrelated
  noise.
