## Item 1 — Gamepad-mode BH telemetry — SHIPPED, BENCH-CONFIRMED

Firmware `a97e9d6`. Gamepad boot on hardware: `hidReady=1`,
`attempts=728 = successes=728` at rest (4.5.0 read `hidReady=0, 0/0`
forever); mouse-mode movement sweep confirmed the counting semantics
(attempts==successes at every sample, `nonzeroReports` climbing,
`maxAbsReport` nonzero).

## Item 2 — Settings-file size budget — SHIPPED, BENCH-CONFIRMED

Firmware `b5899c2` + app `0be7b5c`. Live device: `EX,0:SIZE:377/480` with
all six switch mappings populated (later 379 after the re-center), ~100 B
headroom under the 4.1.0 cliff. The restore round-trip through the flash
also re-verified the packed switch triples byte-exact. The FAIL,3 refusal
path is headroom — unreachable with today's key set, by design.

## Item 3 — LSTimer pool hygiene — SHIPPED, BENCH-CONFIRMED

Firmware `d2d1003` + app `b6056c3` (92-check ASan/UBSan host suite, wired
into `npm test`). Bench: ~37 rapid health checks including a ~150 ms burst
produced **zero** pool prints (the old "No free timers" trigger), and the
unseated-cable degraded episode — a real degraded boot — ran with zero
mid-response prints, no reset loop, and full recovery: the last
bench-pending observation. The safe-mode interval death itself remains
attributed to the now-closed out-of-bounds write vectors (the harness
proved the pool's own logic cannot produce it); the loop()-fed watchdog
stays as belt-and-braces.

## Item 4 — LK remote-control drift — SHIPPED, BENCH-CONFIRMED

Firmware `3e7cc88` + app `c3e037d`. Hardware wire trace of the drift case:
locked select acked `SUCCESS` while `CH,0:0` reported the refusal as page
32 (`MODE_LOCKED_PAGE`), the ~2.6 s follow-up poll landed on Mode @ row 0
exactly as the Hub redrew it. The remote mirror followed device truth.

## Item 5 — XENSIV TLx493D migration — SHIPPED (merged `9b947cc`), FULL PROTOCOL PASSED

Branch `xensiv-tlx493d-migration` @ `5285957`, merged into
`firmware-release-pipeline` with the old TLV493D-A1B6 fork removed in the
merge commit; `dist` rebuilt from the merge (byte-size-identical to the
build the bench validated). Protocol results (see
`xensiv-migration-bench-protocol.md` for the original steps):

- **JV/raw parity** vs the 4.5.0 fork baseline: corner magnitudes ~25–30 mT
  on both libraries, same 0.098 mT/LSB scale, no axis/sign changes.
- **Full four-corner calibration**: clean completion in proper quadrature
  (`17.54|-24.21, -18.72|-22.93, -20.87|13.13, 24.40|11.96`), stored.
- **Z-latch**: `dirX=-1, dirY=1` identical across five restarts.
- **Cursor feel**: signed off at SS=7/AV=3.
- **Flaky bus**: the unseated-cable episode matched the documented
  degraded-state pattern exactly (garbage-ACK rather than the crawl
  variant — both are flaky-bus modes); graceful, no reset loop, recovered.
- **Battery trade: ACCEPTED** — the sensor measures continuously (~mA vs
  µA); USB-powered use pays nothing; BLE untethered runtime is the one
  place it can be felt. Logged for upstream; the powerdown-mode follow-up
  path is documented in the vendored copy's `LIPSYNC.md`.

## Notes for the record (observed during validation, all benign)

- The firmware **re-centers the joystick on every boot**
  (`initJoystick` → `setJoystickInitialization`), and the center completion
  prints `SUCCESS,0:IN,1:<point>` with hardcoded `true,true` — an
  unsolicited SUCCESS when a serial session is open ~2 s after boot. This
  explains the long-observed boot-to-boot neutral "drift" (it is by design)
  and produced one harmless stray line mid-load during validation. Small
  follow-up someday: print MANUAL or stay silent.
- A degraded boot's auto-center can store a garbage-neutral (observed
  `0.00|0.00` during the unseated boot); the corners survive and a clean
  `IN,1:1` restores it — exactly what the bench did.
- `Firmware update check failed: Failed to fetch` lines during validation
  were the app's remote update-check with no server reachable — unrelated
  noise.
