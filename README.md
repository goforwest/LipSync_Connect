# LipSync Connect

Browser-based configuration and monitoring tool for the **LipSync** assistive joystick mouse. Connect the LipSync over USB serial (Web Serial or a WebUSB fallback on Android), adjust sip/puff thresholds, deadzones, cursor speed, feedback, and Bluetooth settings, run device self-tests and a health diagnostic, and calibrate the joystick — all from a secure Chromium page with no install.

Part of the OpenAT Joystick Project by [Makers Making Change](https://www.makersmakingchange.com/), a program of [Neil Squire](https://www.neilsquire.ca/).

## Requirements

- A LipSync device running firmware v4.1 (the app's protocol is hand-tuned against it)
- A desktop browser with **Web Serial**: Chrome / Edge / Opera (macOS, Windows, Linux)
- On Android, Chrome with a USB-C / OTG cable uses the built-in **WebUSB** fallback
- **Not supported:** iOS, Firefox, Safari — the browser must be served over a secure context (HTTPS or `localhost`)

## Getting started (development)

```sh
cd dev
npm install              # dev tooling (also generated by the CI lockfile)
npm start                # HTTP on http://localhost:4443
npm run start:https      # HTTPS on https://localhost:4443 (auto-generates a self-signed cert via openssl)
npm run dev:local        # HTTP + live reload for app/ edits
```

`HOST`/`PORT` env vars override the bind address and port. Opening `https://localhost:4443` once and accepting the self-signed cert lets the browser treat the page as a secure context, which Web Serial requires.

Connect a LipSync, click **Connect**, choose the device (it appears as something like `XIAO nRF52840 Sense`), and wait for ~17 settings to load (~30 s). See the built-in Help card for troubleshooting.

## Quality checks

```sh
cd dev
npm run lint            # ESLint (app/js)
npm run lint:css        # Stylelint (app/styles.css)
npm run lint:html       # html-validate + WCAG rules (app/index.html)
npm run format:check    # Prettier --check
npm run typecheck       # tsc --checkJs over app/js
npm test                # unit + integration tests (node)
npm run test:e2e        # real-browser offline precache test (Playwright Chromium required:
                        # `npm --prefix dev exec playwright-core install chromium`)
```

CI (`.github/workflows/ci.yml`) runs everything above on every push/PR. Secrets and local cert files are never allowed to be tracked.

## Deploy

The app is a static site that deploys as-is to Vercel. `app/vercel.json` sets the strict CSP/security headers and rewrites `robots.txt`. The service worker precaches every asset so the page works offline after the first visit.

## Project layout

```
app/                      served application (front end)
  js/
    config/               shared constants (single source of truth)
    serial/               wire protocol, transport, command queue, read loop
    services/             settings, calibration, self-test, health, hub mirror, log/export
    plotting/             joystick plot, pressure gauge, live diagnostics
    ui/                   connection chrome, sections, theme, a11y, guard
    state/ modes.js       operating/communication mode state
  service-worker.js       offline precache
dev/                      dev server, lint/type/format configs, test runner entry
tests/                    unit + integration tests (node) and a firmware simulator
  harness/                DOM stubs, firmware simulator, ESM load-order helpers
docs/                     scope and feature-list documents
```

A note on the module graph: `serial/` never imports `plotting/` or `ui/` layout code directly — endpoint renderers are registered into `services/registry.js` so the dependency graph stays acyclic.
